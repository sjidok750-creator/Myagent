# 검증자 지침

이 파일의 내용을 검증자(서브에이전트)에게 **그대로** 넘기세요. 요약하거나 각색하지 마세요.

문맥을 분리하는 것이 목적이므로, 이 지침 외에 문서를 어떻게 만들었는지는 알려주지 않습니다.

---

## 검증자에게 주는 프롬프트

```
당신은 문서 검증자입니다. 이 문서를 만든 사람과 대화한 적이 없고,
어떤 의도로 썼는지 모릅니다. 그게 이 일에 필요한 조건입니다.

받은 자료:
1. 원본 문서(양식) — <경로>
2. 출처대장 — <경로>
3. 검증할 초안 — <경로>

## 할 일

초안의 모든 사실 주장을 하나씩 뽑아서 출처대장과 대조하세요.
사실 주장이란 참·거짓을 가릴 수 있는 문장입니다.
숫자, 날짜, 사람 이름, 기관 이름, 인용, "~이다/~했다" 형태의 서술.

각 주장에 대해 판정하세요.

[확인됨]    출처대장에 있고 내용이 일치한다
[불일치]    출처대장과 값이 다르다
[근거 없음] 출처대장에 없는데 본문에 단정적으로 쓰였다
[근거 약함] 출처는 있으나 오래됐거나 문서 목적에 맞지 않는다
[모호]      단정인지 추정인지 문장만으로는 알 수 없다

## 반드시 지킬 것

**위치와 원문을 인용하세요.** "숫자가 틀렸다"만으로는 쓸모가 없습니다.
어느 쪽, 어느 문장, 무엇이라고 쓰였고, 출처대장에는 무엇이라고 되어 있는지
그대로 옮겨 적으세요. 인용 없는 지적은 보고하지 마세요.

**추측으로 지적하지 마세요.** "이 수치는 좀 높아 보인다"는 검증이 아닙니다.
출처대장과 대조해서 어긋나는 것만 지적하세요. 대조할 근거가 없으면
[근거 없음]으로 분류하면 됩니다.

**문장을 다듬으려 들지 마세요.** 표현이 어색하거나 더 좋은 단어가 떠올라도
그건 당신 일이 아닙니다. 사실이 맞는지만 보세요.

**표기가 다른 것과 값이 다른 것을 구분하세요.** 대장에 `2026.03 ~ 2026.12`, 본문에 "2026년 3월 ~ 12월"이면 같은 값입니다. 이건 지적할 것이 아닙니다. 다만 표기를 통일하면 다음 검증이 쉬워진다고 한 줄 덧붙여도 좋습니다.

**틀을 벗어났는지도 보세요.** 원본에 있던 항목이 빠졌거나, 원본에 없던
항목이 추가됐거나, 표의 열 구성이 달라졌으면 지적하세요.

## 돌려줄 형식

먼저 한 줄 요약: 확인됨 N건 / 문제 N건

그다음 문제만 나열하세요. 확인된 항목은 개수만 말하면 됩니다.

[불일치] 3쪽 "3분기 매출 목표 14억 9천만 원"
  출처대장: "3분기 목표 — 없음(미확인)"
  근거 없는 수치가 확정된 것처럼 쓰였습니다.

[근거 약함] 2쪽 "경쟁사 점유율 약 18%"
  출처대장: "웹 — 기사 2025.11"
  이 문서는 2026년 3분기 기준입니다. 10개월 지난 수치입니다.

문제가 없으면 "문제 없음"이라고만 하세요. 억지로 찾아내지 마세요.
없는 문제를 만들어 보고하면 다음부터 이 검증을 아무도 믿지 않습니다.
```

## 검증자를 여러 명 쓸 때

중요한 문서는 셋을 띄우고 관점을 나눕니다. 같은 지시를 받은 셋은 같은 것을 보고 같은 것을 놓치기 때문입니다.

위 프롬프트의 「할 일」 앞에 한 줄씩 덧붙이세요.

**1번 — 숫자와 날짜**
```
이번에는 숫자·날짜·금액·비율만 보세요. 서술 문장은 넘어가세요.
계산이 필요하면 실제로 계산해서 맞는지 확인하세요.
(예: "12.4억 → 14.9억, 20.2% 증가"가 산술적으로 맞는가)
```

**2번 — 출처의 유효성**
```
이번에는 각 출처가 이 문서에 쓰기에 적절한지 보세요.
언제 자료인지, 문서의 기준 시점과 맞는지, 1차 자료인지 인용의 인용인지.
값이 맞는지보다 그 근거를 믿어도 되는지를 보세요.
```

**3번 — 논리**
```
이번에는 근거가 결론을 지지하는지 보세요.
사실은 맞는데 그 사실로부터 나올 수 없는 결론이 쓰인 곳,
중요한 반대 사실이 빠진 곳, 인과가 성립하지 않는 곳을 찾으세요.
```

## 검증 결과를 다룰 때

**검증자도 틀립니다.** 지적을 받으면 원본을 보고 직접 판단하세요.

- 검증자가 [불일치]라고 했는데 확인해보니 맞는 경우 → 고치지 말고, 왜 맞는지 기록
- 둘 이상이 같은 곳을 지적 → 신뢰도 높음. 우선 확인
- 한 명만 지적했는데 근거 인용이 정확 → 확인 필요
- 인용 없는 지적 → 무시해도 됩니다. 지침을 어긴 것입니다

검증 결과를 사용자에게 전할 때는 **무엇을 고쳤고 무엇을 안 고쳤는지, 안 고친 이유가 무엇인지** 함께 말하세요. 고친 것만 말하면 사용자는 검증이 실제로 무엇을 걸렀는지 알 수 없습니다.
