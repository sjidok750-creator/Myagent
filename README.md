# 헤뤼싀 (Harshi) — 나의 AI 비서실장

아이폰 **메시지(iMessage)** 앱과 똑같이 생긴 화면에서 대화하는, 나 한 사람만을 위한 AI 비서실장입니다.

헤뤼싀는 인도 케랄라 출신의 34세 여성입니다. 뭄바이에서 전략 컨설턴트로, 싱가포르 패밀리오피스에서 총괄 비서로 일했고, 지금은 당신의 비서실장입니다. 한국어로 말하고, 가끔 힌디어가 섞입니다.

혼자 일하지 않습니다. **여덟 개 부서**를 거느리고, **실제로 일을 합니다** — 웹을 찾아보고, 계산하고, 엑셀·문서·발표자료를 만들고, 알게 된 것을 자료실에 적어둡니다.

## 헤뤼싀가 실제로 할 수 있는 일

말만 하는 챗봇이 아닙니다. 대화 도중 필요하면 알아서 도구를 씁니다.

| 도구 | 어디서 도나 | 무엇을 하나 |
|---|---|---|
| 🔍 웹 검색 · 페이지 읽기 | Anthropic 서버 | 오늘의 사실을 직접 찾아본다. 링크를 주면 열어서 읽고 요약한다. |
| ⚙️ 코드 실행 | Anthropic 샌드박스 | 계산·표 정리·데이터 분석. 암산으로 어림잡지 않는다. |
| 📊 파일 만들기 | 코드 실행 + Agent Skills | 엑셀(xlsx)·워드(docx)·발표자료(pptx)·PDF 를 만들어 대화창에 첨부한다. |
| 📎 파일 읽기 | Files API | 사진·PDF·문서를 보내면 그대로 읽는다. 엑셀·워드는 코드로 열어서 본다. |
| 🗓️ 구글 캘린더 | 대표님 계정 | 일정을 조회·생성·수정·삭제한다. 잡기 전에 빈 시간을 먼저 확인한다. |
| ✉️ 지메일 | 대표님 계정 | 메일을 검색하고 읽는다. 답장은 **초안까지만** — 발송은 대표님이 누른다. |
| 🗂️ 비서실 자료실 | 이 기기 | 메모·할 일·사람을 적고 찾는다. **여덟 팀이 같은 자료실을 본다.** |
| 🔔 아침 브리핑 | 서버 크론 | 예약한 시각에 **헤뤼싀가 먼저** 오늘 일정과 챙길 일을 보낸다. |

실제로 이런 식으로 씁니다.

- "이번 달 지출 정리해줘" → 계산하고 **엑셀 파일**을 만들어 첨부. 요약은 자료실에 메모로 저장.
- "이 회사 어떤 곳이야?" → **웹에서 찾아보고** 출처와 함께 보고. 알게 된 사실은 메모로 남김.
- "다음 주 화요일에 미팅 잡아줘" → **할 일로 등록**. 자료실 탭에서 눈으로 확인·완료 처리 가능.
- "김파트너 기억해둬" → **사람으로 기록**. 나중에 어느 부서에서 물어도 안다.
- "IR 덱 초안 만들어줘" → **pptx 파일**로 만들어 첨부.
- 영수증 사진을 여러 장 보내고 "정리해줘" → 사진을 **읽어서** 합계를 내고 엑셀로 정리.
- 계약서 PDF를 보내고 "독소조항 있어?" → **PDF를 정독**하고 조항별로 짚어줌.
- "내일 오전 비어? 김파트너랑 10시에 잡아줘" → **실제 구글 캘린더**를 확인하고 일정 생성.
- "김파트너한테 온 메일 찾아서 답장 써줘" → **지메일 검색 → 정독 → 답장 초안**. 보내기는 내가 누름.

### 자료실 — 부서를 잇는 공용 기억

부서 대화방은 각각 독립된 대화지만, **자료실은 하나**입니다. 재무팀에 말한 내용을 일정팀도 압니다. 대화 목록 오른쪽 위 폴더 아이콘으로 열면 할 일·메모·사람을 직접 보고, 체크하고, 지울 수 있습니다.

자료실은 대화 요청마다 서버로 함께 보내지고, 헤뤼싀가 도구로 고친 결과가 되돌아와 기기에 저장됩니다. **서버는 아무것도 저장하지 않습니다.**

### 도구 끄기

설정 → "헤뤼싀가 쓸 수 있는 것" → 도구 사용을 끄면 대화만 합니다. 더 빠르고 저렴합니다. (직접 연결 모드에서는 도구를 쓸 수 없습니다 — 도구 루프는 서버에서 돕니다.)

### 파일·사진 보내기

작성창 왼쪽 **+** 를 누르면 사진 보관함과 파일에서 고를 수 있습니다. 한 번에 6개까지, 파일당 20MB 까지.

| 보낸 것 | 헤뤼싀가 하는 일 |
|---|---|
| 사진 (jpg/png/…) | 눈으로 보고 읽습니다. 보내기 전에 긴 변 1568px 로 줄여 토큰을 아낍니다. |
| PDF | 문서로 통째로 읽습니다. |
| 텍스트·CSV·JSON | 문서로 읽습니다. |
| 엑셀·워드·PPT | 코드 실행 컨테이너에 올려 코드로 열어 봅니다. |

한 번 보낸 파일은 Anthropic Files API 에 올라가고, 기기가 그 `file_id` 를 기억합니다. 같은 대화에서 다시 언급해도 **다시 업로드하지 않습니다.**

### 헤뤼싀가 만든 첨부파일

헤뤼싀가 만든 파일은 대화창에 카드로 붙습니다. 탭하면 아이폰 공유 시트가 떠서 "파일에 저장"·"메일로 보내기"를 쓸 수 있습니다. 파일 본체는 기기의 IndexedDB에 보관되고(최대 80MB, 넘치면 오래된 것부터 정리), 서버에는 남지 않습니다.

---

### 얼굴 사진 바꾸기

기본 아바타는 코드로 그린 일러스트입니다. 원하는 사진으로 바꿀 수 있습니다.

**설정 → 헤뤼싀 얼굴 → 사진 고르기**, 또는 대화방 오른쪽 위 ⓘ → 프로필 사진을 탭.
조직도에서 팀을 고르면 팀장 얼굴도 각각 바꿀 수 있습니다.

고른 사진은 256px 정사각형으로 잘려 **이 기기의 localStorage에만** 저장됩니다. 저장소에 커밋되지도, 서버로 올라가지도 않습니다. 언제든 "기본 일러스트로 되돌리기"로 원복됩니다.

---

부서는 두 가지 방식으로 쓸 수 있습니다.

1. **헤뤼싀 방에 그냥 던지기** — 실장이 알아서 담당 팀을 정해 처리하고, 말풍선 위에 어느 팀이 맡았는지 배지가 붙습니다.
2. **부서 방에 직접 들어가기** — 대화 목록에서 팀을 고르면 그 팀장과 1:1로 이야기합니다. 각 팀장은 자기 부서의 원칙(예: 재무팀은 계산 과정을 반드시 한 줄로 보여준다)에 따라 답합니다.

## 아이폰에서 앱처럼 쓰기

1. 사파리로 배포한 주소를 엽니다.
2. 하단 **공유 버튼** → **홈 화면에 추가**.
3. 홈 화면 아이콘으로 열면 주소창 없이 전체 화면으로 뜹니다.

다크 모드, 세이프 에어리어(노치·홈 인디케이터), 키보드 높이 대응이 모두 들어 있습니다.

## 어디에 배포하나

코드는 이미 GitHub 에 있습니다. 다만 **GitHub Pages 는 정적 파일만 서빙**해서 서버 기능이 돌지 않습니다. 두 갈래가 있습니다.

| | GitHub Pages | Vercel |
|---|---|---|
| 준비물 | GitHub 계정만 | GitHub + Vercel 계정 |
| 대화 | ✅ (설정에서 “직접 연결” 모드) | ✅ |
| 헤뤼싀 인격·부서·자료실 | ✅ | ✅ |
| 웹 검색·코드 실행·파일 생성 | ❌ | ✅ |
| 사진·PDF 읽기 | ❌ | ✅ |
| 구글 캘린더·지메일 | ❌ | ✅ |
| 먼저 말 걸기(알림) | ❌ | ✅ |
| API 키가 있는 곳 | **이 기기 localStorage** | 서버 환경변수 |

서버 기능은 전부 서버리스 함수(`api/`)가 필요해서 정적 호스팅으로는 안 됩니다. 구글 연결은 클라이언트 시크릿을, 알림은 저장소와 크론을 요구합니다.

**둘 중 하나만 고르실 필요는 없습니다.** GitHub Pages 로 먼저 써 보시고, 손이 필요해지면 같은 저장소를 Vercel 에 연결하시면 됩니다.

### 갈래 A — GitHub Pages (제일 빠름, 대화만)

1. 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 바꿉니다.
2. 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 알아서 배포합니다.
3. 나온 주소를 아이폰 사파리로 열고 → 공유 → **홈 화면에 추가**
4. 앱에서 설정 → **연결 모드 → 직접 연결** → Anthropic API 키 입력

> ⚠️ 이 방식은 API 키가 **이 기기의 localStorage** 에 저장됩니다. 본인 폰에서만 쓰세요.
> 주소는 공개지만 키가 없으면 누구도 대화할 수 없습니다.

### 갈래 B — Vercel (전부 다 됨)

**CLI 없이 GitHub 연결만으로 됩니다.**

1. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → `sjidok750-creator/Myagent` 선택
2. Framework Preset 은 **Other**, 나머지는 기본값 그대로
3. **Environment Variables** 에 아래 표의 값을 넣고 **Deploy**
4. 이후 이 브랜치에 푸시할 때마다 자동으로 다시 배포됩니다

CLI 를 선호하시면 `npx vercel --prod` 도 됩니다.

### 갈래 C — 로컬 브릿지 (구독으로 · API 과금 없음 · 권장)

배포하지 않는 갈래입니다. 주력 컴퓨터에서 서버를 켜 두고, 같은 네트워크의 휴대폰이 접속합니다. 뒤에서는 그 컴퓨터에 설치된 **Claude Code CLI(구독 로그인)** 가 돌기 때문에 API 키도, 과금도 없습니다.

```
아이폰 (iMessage 화면) → 컴퓨터의 브릿지 서버 → claude CLI (구독)
```

```bash
git clone https://github.com/sjidok750-creator/Myagent.git
cd Myagent
HERUSHI_CODE=원하는코드 npm run herushi
# 화면에 나온 http://<컴퓨터IP>:5177 을 아이폰 사파리로 열고 홈 화면에 추가
# 앱 설정 → 접속 코드에 같은 코드 입력
```

전제: 그 컴퓨터에 [Claude Code](https://claude.com/claude-code)가 설치되어 있고 로그인돼 있어야 합니다 (`claude` 한 번 실행해서 확인).

| | 이 갈래에서 |
|---|---|
| 대화 · 부서 · 인격 | ✅ |
| 웹 검색, 파일 만들기 | ✅ CLI 도구로 |
| 만든 파일 폰으로 받기 | ✅ 작업 폴더에 저장되면 자동 전송 |
| 사진·파일 첨부 | ✅ 작업 폴더 `받은파일/`에 저장됨 (받은 것만 — 만든 것이 여기 저장되면 브릿지가 작업 폴더로 도로 옮깁니다) |
| **한글(HWP) 문서, 스킬** | ✅ `~/.claude/skills/`의 스킬 그대로 — 다른 갈래는 못 함 |
| 컴퓨터 폴더 작업 | ✅ 과업 방이면 그 과업 폴더, 실장님 방이면 작업 폴더 전체 |
| 구글 캘린더·지메일, 먼저 말 걸기 | ❌ (Vercel 갈래만) |
| 컴퓨터가 꺼져 있을 때 | ❌ 브릿지도 잠듭니다 |

#### 방 = 과업 폴더

대화 목록은 **실장님 방 하나 + 지금 돌아가는 과업 방들**입니다. 부서 여덟 개는 없앴습니다 — 어차피 CLI 하나가 다 처리해서 장식이었고, 대표님 일의 축은 부서가 아니라 과업이기 때문입니다.

방은 등록 장부가 아니라 **파일 하나**로 존재합니다.

```
D:\2026년 과업\D. 숙골교등 6개소\
├── _방.md          ← 이게 있으면 방이 있다. 목록에 뜬다
├── CLAUDE.md       ← 그 과업 지침 (발주처·구조물 형식·보고서 목차)
├── _기록\          ← 헤뤼싀와 나눈 대화
└── _검증\          ← 코덱스와 주고받은 전문
```

- **실장님 방에서 과업 일을 시키면** 헤뤼싀가 그 폴더에 `_방.md` 를 만들고 "그 방에서 이어가겠습니다" 하고 넘깁니다. 폴더가 어디인지만 한 번 확인하고, 발주처·기간처럼 폴더를 보면 아는 것은 되묻지 않습니다.
각 과업 방에는 **담당자가 있습니다.** `_방.md` 의 `담당:` 줄에 적힙니다.

```markdown
# D. 숙골교등 6개소
담당: 카비야 · 현장 담당

착수일 확인 후 잔여기간 산정
```

헤뤼싀가 방을 만들 때 정합니다. 그 방에서는 헤뤼싀가 아니라 그 사람이 답하고, 대화 목록에도 그 이름과 직책이 뜹니다. 직접 고쳐도 됩니다 — 이름만 쓰면 직책은 `과업 책임`이 되고, `담당:` 줄이 아예 없으면 방 id 에서 자동으로 정해집니다(폴더 경로가 그대로면 늘 같은 사람입니다).

- **과업 방에서는** 그 폴더가 곧 작업 폴더입니다. `cwd` 가 그 폴더라 **그 폴더의 `CLAUDE.md` 와 상위 폴더의 `CLAUDE.md` 가 자동으로 적용됩니다**(Claude Code 가 폴더를 거슬러 올라가며 읽습니다). 만든 파일도 거기 남고, 코덱스도 `--cd` 가 그 폴더라 딴 과업에 헷갈리지 않습니다.
- **끝나면** 대표님이 "이 과업 끝났어"라고 하실 때만 `_방.완료.md` 로 이름이 바뀝니다. 목록에서 내려가지만 **지우지 않습니다** — 방을 지우면 폰에 쌓인 그 대화도 같이 사라지고, 두 달 뒤 발주처가 "그때 왜 C등급이었나" 물으면 늦습니다. 그 방에 다시 말을 걸면 헤뤼싀가 "다시 여실까요?" 하고 먼저 여쭙니다.

방 목록은 브릿지가 `/api/rooms` 로 알려주고, 헤뤼싀가 방을 만들거나 닫으면 그 턴이 끝날 때 화면이 바로 갱신됩니다.

#### 화면을 벗어나도 일은 계속되고, 돌아오면 이어서 보인다

작업은 요청이 아니라 **방에 매여** 있습니다. 폰이 화면을 벗어나 연결이 끊겨도 헤뤼싀는 계속 일하고, 그동안 일어난 일을 기록해 둡니다. 다시 그 방을 열면(앱을 다시 켜거나 화면으로 돌아오면) 자동으로 다시 붙어서 —

| 돌아왔을 때 상태 | 보이는 것 |
|---|---|
| 아직 일하는 중 | 지금까지의 진행 상황이 재생되고, 이어서 실시간으로 계속 보임 |
| 이미 끝났음 | 📨 로 **못 받아 간 부분만** 배달됨 |
| 아무 일도 없었음 | 조용히 아무것도 안 함 |

일하는 중에 새 메시지를 보내면 **새 작업을 시작하지 않고** 지금 하는 일을 보여줍니다. 같은 방에 두 프로세스가 붙으면 세션 기록이 뒤섞이기 때문입니다.

보관은 "아무도 안 보고 있었나"가 아니라 **"폰이 무엇을 받아 가지 못했나"**로 정합니다. 답을 다 읽고 화면을 벗어난 뒤 마무리(파일 수집·검증)가 몇 초 더 걸려서 끝나는 일이 흔한데, 그때 통째로 보관하면 다시 들어올 때 같은 답이 📨 로 한 번 더 뜹니다.

연결이 끊긴 것 자체는 **실패가 아니므로 실패 말풍선을 띄우지 않습니다.** 서버가 `done`을 보내기 전에 스트림이 닫히면 화면은 그것을 '끊김'으로 보고, 그리다 만 조각을 지운 뒤 다시 붙습니다(1.5초부터 최대 15초까지 간격을 늘려 가며, 화면으로 돌아왔을 때도 즉시). 다시 붙으면 서버가 처음부터 재생해 주므로 같은 말이 두 번 쌓이지 않습니다.

검증 친구(코덱스)가 붙으면 이 구조가 특히 중요해집니다 — 검증 왕복은 몇 분씩 걸려서 그 사이 폰은 거의 확실히 화면을 벗어나는데, 그래도 검증은 끝까지 진행되고 돌아와서 전 과정을 볼 수 있습니다.

#### 헤뤼싀와 나눈 대화를 CLI 에서 여는 법

**`claude --resume` 목록(picker)에는 헤뤼싀 방이 뜨지 않습니다.** 브릿지는 `claude -p`(비대화형)로 도는데, 그렇게 만든 세션은 목록에서 빠집니다.

빠지는 것이지 없는 것이 아닙니다. 나눠 보면:

| | |
|---|---|
| 기록이 디스크에 남는다 | ✅ `~/.claude/projects/<작업폴더>/<세션ID>.jsonl` |
| `claude --resume <세션ID>` 로 열린다 | ✅ 기억까지 그대로 이어집니다 |
| `claude --resume` **목록에 뜬다** | ❌ 안 뜹니다 |

실제 사용자 컴퓨터에서 확인한 수치: 작업 폴더에 세션 5개(브릿지가 만든 것 4 + 사람이 직접 연 것 1)가 있는데 목록에는 1개, 그 사람이 직접 연 것만 떴습니다.

그래서 **`헤뤼싀책상.bat`** 이 필요합니다 — 목록을 거치지 않고 `.sessions.json` 의 ID 를 직접 넘깁니다. 어느 세션이 어느 방인지는 `헤뤼싀기록.bat` 이 알려줍니다.

두 가지를 더 챙깁니다.

1. **방마다 세션이 딱 하나입니다.** 브릿지는 매번 같은 세션을 `--resume` 로 이어받습니다(그래야 헤뤼싀가 어제 한 일을 기억합니다). 세션 ID 는 CLI 가 알려주는 즉시(첫 `init` 이벤트) 적어 둡니다. 예전에는 턴이 성공했을 때만 적어서, 중간에 죽은 턴 뒤에는 새 세션이 만들어지고 앱의 대화가 통째로 다시 밀려 들어갔습니다 — 실제로 그렇게 버려진 세션이 남아 있었습니다.
2. **제목을 붙입니다.** `--name` 으로 `헤뤼싀 · 실장님 방` 처럼. 목록에는 안 뜨지만 `헤뤼싀기록.bat` 과 데스크톱 앱에서 알아보기 위해서입니다.

여기에 더해, 대화할 때마다 사람이 읽는 기록을 작업 폴더의 `_헤뤼싀일지\` 에 날짜별로 남깁니다.

```
D:\_헤뤼싀일지\2026-08-24.md
```

메모장이나 아무 편집기로 열리고, 필요 없는 날은 파일째 지우면 됩니다. 헤뤼싀 자신도 다음에 이 파일을 읽을 수 있어서 "지난주에 나랑 뭐 했지?" 같은 질문에도 답합니다. 이 폴더 자체는 대화창에 파일로 전송되지 않습니다(내부 기록이지 결과물이 아니므로).

#### 어느 대화가 헤뤼싀 방인지 찾기

```
헤뤼싀기록.bat            작업 폴더에서 만들어진 대화만
헤뤼싀기록.bat 전부        이 컴퓨터의 모든 대화
```

> 배치 파일에서 `npm` 을 부를 때는 반드시 `call npm ...` 이어야 합니다. 윈도우의 `npm` 은 `npm.cmd` 이고, 배치에서 다른 배치를 `call` 없이 부르면 **제어가 돌아오지 않습니다** — npm 이 끝나는 순간 창이 닫히고 뒤의 `pause` 는 실행조차 안 됩니다. 세 launcher 모두 이 문제가 있었습니다.

기록 파일(`~/.claude/projects/**/<세션ID>.jsonl`)을 직접 읽어 보여줍니다. 이어받기 목록의 제목은 첫 질문에서 자동으로 지어져 구별이 안 되지만, 기록에는 **어디서(`cwd`) 무엇으로(`entrypoint`) 만들어졌는지**가 남아 있습니다.

```
  작업 폴더   D:\
  기록 폴더   C:\Users\...\.claude\projects
  찾은 대화   전체 22개 · 작업 폴더에서 만들어진 것 2개

  ── D:\ 에서 만들어진 대화 ──

  ★ 헤뤼싀 · 실장님 방              128번    4.2MB  08-24 18:31  [폰]
      4146ed68-fbfd-4598-aecd-18d4d231e56a
      첫 질문: 오늘 뭐 챙겨야 하지?
      → .sessions.json 의 실장님 방  ·  헤뤼싀책상.bat 로 이어받습니다

    D드라이브 구조 확인                 1번     59KB  08-24 17:02  [책상]
      abc12345-...
      첫 질문: D드라이브 구조 확인해줘
```

- **★** — `.sessions.json` 이 가리키는 방. 헤뤼싀가 쓰는 그 대화입니다.
- **[폰]** — 브릿지(`claude -p`)가 만든 것. **[책상]** — 사람이 CLI 에서 직접 연 것.
- 횟수는 대표님이 실제로 친 것만 셉니다(도구 결과도 기록에는 `type:"user"` 로 남지만 빼고 셉니다).

작업 폴더에서 만들어진 대화가 **0개**로 나오면 브릿지가 다른 폴더에서 돌았거나 설정 폴더(`CLAUDE_CONFIG_DIR`)가 다른 것입니다 — 그 경우도 그렇게 말해 줍니다.

#### 헤뤼싀가 끝낸 작업을 책상에서 이어받기

```
헤뤼싀책상.bat            방 목록에서 고른다
npm run herushi:desk      같은 것 (터미널에서)
```

```
  이어받을 방을 고르세요.

    1. 실장님 방        128번 주고받음 ·  4.2MB · 마지막 08-24 18:31
       4146ed68-fbfd-4598-aecd-18d4d231e56a
    2. 프로젝트·실행팀     9번 주고받음 ·   210KB · 마지막 08-23 11:04
       518e930e-c8ab-5a4d-8f22-caf3ba3136c3
```

방을 고르면 그 대화를 그대로 이어받습니다. 손으로 세션 ID를 찾을 필요가 없습니다 — `.sessions.json` 에서 찾아 `claude --resume` 을 대신 실행합니다.

**`claude --resume` 목록에서 눈으로 고르지 마세요.** 제목은 첫 질문에서 자동으로 지어져 헤뤼싀 방과 구별이 안 됩니다. 위 목록의 주고받은 횟수·크기·시각이 어느 것이 헤뤼싀 방인지 말해 줍니다.

한 방의 대화는 **파일 하나에 계속 쌓입니다.** `-p --resume` 을 반복해도 세션 ID 는 그대로이고 기록이 누적된다는 것을 실제 CLI 로 확인했습니다(3턴을 이어 물어 세션 ID 1개·기록 1개·기억 유지).

| 챙기는 것 | 왜 |
|---|---|
| `--resume <세션ID>` | 폰에서 한 대화가 그대로 이어집니다 |
| 인수인계 쪽지 (`--append-system-prompt`) | **책상에서는 헤뤼싀가 아니라 클로드 코드와 일합니다.** 기록에 남은 비서 말투를 그냥 이어받으면 계속 비서를 연기하고, 앞선 `[[dept:...]]` 태그를 프롬프트 인젝션으로 의심하기까지 합니다(실측). 쪽지가 "맥락은 이어받되 인격은 내려놓아라"를 명시합니다 |
| `--name 헤뤼싀 · 실장님 방` | 이어받기 목록에서 알아보기 위해 |
| 자물쇠 | **한 세션 파일을 폰과 책상이 동시에 쓰면 기록이 깨집니다.** 책상 창이 열려 있는 동안 그 방에 폰으로 말을 걸면 헤뤼싀가 "지금 책상에서 열어 두셨습니다" 하고 받지 않습니다. 다른 방은 그대로 됩니다. 창을 닫으면 풀립니다 |

자물쇠는 창을 닫을 때 풀리고, 컴퓨터가 갑자기 꺼져서 남더라도 그 프로세스가 죽어 있으면 무시합니다.

쓰는 흐름은 이렇습니다.

```
밖에서 폰으로 지시  →  헤뤼싀가 작업을 끝냄  →  책상에 앉음
                                                    ↓
                                          헤뤼싀책상.bat
                                                    ↓
                     그 작업 맥락 그대로, 클로드 코드와 직접 파일을 고침
                                                    ↓
                              창을 닫으면 폰에서 다시 이어짐
```

책상에서 고친 내용은 같은 세션에 쌓이므로, 폰으로 돌아가면 헤뤼싀도 그것을 알고 있습니다. 나중에 검증 친구(코덱스)와 주고받은 결과물을 책상에서 손보는 것도 같은 길입니다.

실제 CLI 로 확인한 것: 헤뤼싀 인격으로 파일을 요약시킨 세션(`[[dept:ops]] 도넛팀장님…`)을 쪽지와 함께 이어받아 "지금 너는 헤뤼싀야?" 라고 물으면 **"아니요, 평소의 Claude Code 입니다"** 라고 답하고, 앞의 작업 맥락은 유지한 채 파일을 실제로 고쳤습니다(0.3mm → 0.5mm).

#### 검증 친구 — 다른 회사 모델의 교차 검토

같은 컴퓨터에 [OpenAI Codex CLI](https://github.com/openai/codex)를 설치하고 ChatGPT 유료 계정으로 로그인해 두면, **헤뤼싀의 결과를 코덱스가 같은 대화방에서 검토합니다.** 헤뤼싀가 파일을 만들거나 실질적인 답을 하면 → 코덱스가 요청·답·파일만 받아 백지 상태에서 대조하고(과정과 의도는 주지 않습니다) → 지적이 있으면 헤뤼싀가 원본을 다시 확인해 고치거나, 근거를 들어 반박합니다. 세 말풍선이 다 대화방에 남습니다.

```bash
npm i -g @openai/codex   # 또는 brew install --cask codex
codex login              # ChatGPT Plus/Pro 계정
```

브릿지가 켜질 때 로그인까지 확인해서, 준비 안 됐으면 검증 없이 조용히 돕니다.

**합의될 때까지 주고받습니다.** 코덱스가 "문제 없음"이라고 할 때까지 검토→수정→재확인이 반복됩니다. 끝없이 돌지 않도록 둘을 둡니다: 코덱스가 **같은 지적을 되풀이하면** 평행선으로 보고 멈추고, 최대 라운드(기본 4)에 걸려도 멈춥니다. 합의 없이 끝나면 *"의견이 갈립니다 — 대표님이 판단해 주세요"* 라고 대화방에 남깁니다.

| 환경변수 | 기본 | 뜻 |
|---|---|---|
| `HERUSHI_VERIFY` | `auto` | `auto` 파일 생성·실질 답변만 검토 · `always` 전부 · `off` 끔 |
| `HERUSHI_VERIFY_ROUNDS` | `4` | 최대 왕복 횟수 |
| `HERUSHI_VERIFIER` | `codex` | 검증 백엔드. `codex` 또는 `claude` |
| `HERUSHI_VERIFIER_NAME` | 백엔드마다 | 대화방에 표시될 이름 |
| `HERUSHI_VERIFIER_CMD` | 백엔드마다 | 실행 파일 이름 |

##### 검증자를 다른 모델로 바꾸기

검증의 값어치는 **뇌가 다른 데서** 나옵니다. 껍데기(CLI 규약)는 같아도 됩니다.
그래서 `HERUSHI_VERIFIER=claude` 를 쓰면 Claude Code 규약을 따르는 아무 백엔드나
검증자로 끼울 수 있습니다. [GLM Coding Plan](https://z.ai) 처럼요.

| 환경변수 | → |
|---|---|
| `HERUSHI_VERIFIER_URL` | `ANTHROPIC_BASE_URL` |
| `HERUSHI_VERIFIER_TOKEN` | `ANTHROPIC_AUTH_TOKEN` |
| `HERUSHI_VERIFIER_MODEL` | `--model` |
| `HERUSHI_VERIFIER_CONFIG` | `CLAUDE_CONFIG_DIR` (검증자 전용 설정 폴더) |

```bat
set HERUSHI_VERIFIER=claude
set HERUSHI_VERIFIER_NAME=GLM
set HERUSHI_VERIFIER_URL=https://api.z.ai/api/anthropic
set HERUSHI_VERIFIER_TOKEN=여기에토큰
set HERUSHI_VERIFIER_MODEL=glm-5.3
```

**이 값들은 검증자 프로세스에만 들어갑니다.** 헤뤼싀 본인은 그대로 Claude 구독으로
돕니다. 셸에 `ANTHROPIC_BASE_URL` 을 직접 잡으면 헤뤼싀까지 딸려가니 그러지 마세요.

`claude` 백엔드는 읽기 도구(`Read` `Glob` `Grep`)만 허용하고 `Write` `Edit` `Bash` 는
막습니다 — 코덱스의 `--sandbox read-only` 에 해당합니다. 다만 브릿지가 켜질 때
확인할 수 있는 것은 **설치뿐**입니다. 주소·토큰이 맞는지는 첫 검증에서 드러납니다.
`HERUSHI_VERIFIER=claude` 인데 `HERUSHI_VERIFIER_URL` 이 없으면 검증자가 헤뤼싀와
같은 모델이 되므로 서버 창이 경고합니다. 자기 답의 맹점은 자기가 못 봅니다.

> **자료가 어디로 가는지 먼저 보세요.** 검증자에게는 결과물만이 아니라 `--cd` 로
> **그 과업 폴더 전체를 읽을 권한**이 갑니다. 계약서·현장 자료가 그 안에 있습니다.
> 코덱스는 OpenAI(미국), GLM 은 Zhipu(중국) 서버로 갑니다. 관급 용역 계약서에는
> 자료 국외반출·제3자 제공 제한 조항이 흔합니다. 붙이기 전에 계약 조건을 확인하세요.

서버 창에 매 턴 토큰 사용량이 찍힙니다 — `[herushi] 헤뤼싀 — 입력 9.2k(캐시적중 47.5k) 출력 458`. 실제 소모를 눈으로 확인하고 라운드 수를 조절하세요.

검증자는 읽기 전용으로 돌고, 매번 기억 없이 시작합니다(코덱스는 `--sandbox read-only --ephemeral`). 같은 것을 두 번 보게 하지 않기 위해서가 아니라, **만든 사람의 문맥이 검증자에게 스며들지 않게** 하기 위해서입니다.

알아둘 것:

- **기본 설정은 헤뤼싀가 그 컴퓨터에서 명령(Bash)을 실행할 수 있습니다.** 한글 문서 스킬이 이를 요구합니다. 꺼리면 `HERUSHI_TOOLS=WebSearch,WebFetch,Read,Write,Edit,Glob,Grep` 처럼 좁혀서 켜세요.
- **작업 폴더가 아주 크면**(`D:\` 전체 등) 답이 끝난 뒤 새 파일을 찾느라 몇 초가 더 걸립니다. 기본 6초까지만 쓰고 멈추며, 다 못 훑으면 대화창과 서버 창에 그렇게 알립니다. `HERUSHI_SCAN_MS` 로 늘릴 수 있습니다. 그냥 대화만 한 턴에서는 아예 훑지 않습니다.
- **그 컴퓨터의 Claude Code 에 MCP 서버(구글 캘린더 등)가 붙어 있어도 기본으로는 막힙니다.** 허용 목록에 없는 도구는 헤뤼싀가 부르는 순간 거절됩니다. 기본 목록을 통째로 다시 쓰지 말고 얹으세요 — `HERUSHI_TOOLS_EXTRA=mcp__Google_Calendar,mcp__Gmail`. 얹으면 헤뤼싀 지침의 "없는 기능" 목록에서도 빠집니다.
- `HERUSHI_CODE` 없이 켜면 같은 네트워크의 누구나 접속할 수 있습니다. 꼭 넣으세요.
- 외부에서도 쓰려면 [Tailscale](https://tailscale.com)을 컴퓨터와 폰에 깔고 Tailscale IP 로 접속하면 됩니다. 포트포워딩으로 인터넷에 직접 여는 것은 권하지 않습니다.
- 대화 기억은 방(부서)별로 CLI 세션에 이어집니다 (`작업폴더/.sessions.json`).

## 구글 연결하기 (캘린더 · 지메일)

일정과 메일을 실제로 다루려면 구글 OAuth 클라이언트가 하나 필요합니다. 한 번만 만들면 됩니다.

### 1. 구글 클라우드 콘솔에서 클라이언트 만들기

1. [console.cloud.google.com](https://console.cloud.google.com) 에서 프로젝트를 하나 만듭니다.
2. **API 및 서비스 → 라이브러리** 에서 다음 둘을 사용 설정합니다.
   - Google Calendar API
   - Gmail API
3. **API 및 서비스 → OAuth 동의 화면**
   - User Type: **외부**
   - 앱 이름: 헤뤼싀 (아무거나)
   - **테스트 사용자** 에 본인 지메일 주소를 추가합니다. (게시하지 않아도 본인은 쓸 수 있습니다)
   - 범위는 따로 추가하지 않아도 됩니다. 앱이 요청할 때 함께 뜹니다.
4. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 리디렉션 URI** 에 배포 주소를 **끝의 슬래시까지 정확히** 넣습니다.
     - 예: `https://myagent.vercel.app/`
     - 로컬 개발도 쓰려면 `http://localhost:5173/` 도 함께 추가합니다.
5. 만들어진 **클라이언트 ID** 와 **클라이언트 보안 비밀번호** 를 복사합니다.

### 2. 배포 환경변수에 넣기

```
GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxx
```

### 3. 앱에서 연결

설정 → **구글 연결** → "구글 계정 연결하기". 동의 화면에서 권한을 **모두** 허용해야 캘린더와 메일이 다 동작합니다.

### 요청하는 권한

| 범위 | 왜 필요한가 |
|---|---|
| `calendar.events` | 일정 생성·수정·삭제 |
| `calendar.readonly` | 빈 시간 확인, 일정 조회 |
| `gmail.readonly` | 메일 검색·정독 |
| `gmail.compose` | 답장 **초안** 생성 |

### 메일 발송은 왜 두 단계인가

헤뤼싀에게는 메일을 보내는 도구가 **아예 없습니다.** `gmail_draft` 로 초안만 만들 수 있습니다. 초안이 만들어지면 대화창에 카드가 뜨고, 대표님이 **보내기** 를 눌러야 `/api/google/send` 가 호출됩니다. 모델이 혼자 판단해서 메일을 보내는 경로는 코드상 존재하지 않습니다.

일정 삭제와 참석자 초대는 도구로 가능하지만, 프롬프트에서 실행 전 확인을 요구합니다.

### 토큰은 어디에 있나

구글 액세스·리프레시 토큰은 **이 기기의 localStorage** 에만 저장됩니다. 서버(`/api/google/token`)는 클라이언트 시크릿이 필요한 교환·갱신만 중계하고 토큰을 보관하지 않습니다. 대화할 때마다 기기가 액세스 토큰을 함께 보내고, 서버는 그 요청 동안만 씁니다.

연결을 끊으려면 설정 → 구글 연결 → **연결 해제** (구글 쪽 권한도 함께 회수됩니다).

## 먼저 말 걸게 하기 (아침 브리핑)

예약한 시각에 헤뤼싀가 알림으로 먼저 말을 겁니다. 알림을 탭하면 대화방이 열리고, 그 브리핑이 **말풍선으로 남아 있습니다.** 앱을 안 열어도 대화에 쌓입니다.

> **이 기능만 서버가 무언가를 저장합니다.**
> 다른 모든 것(대화·자료실·구글 토큰)은 기기에만 있지만, 헤뤼싀가 기기 없이 먼저 말을 걸려면 서버가 알림 주소를 알아야 합니다. 무엇을 저장할지는 설정에서 직접 고르실 수 있고, 알림을 끄면 서버에서 지워집니다.

### 저장되는 것

| 항목 | 언제 | 왜 |
|---|---|---|
| 푸시 구독 주소·암호화 키 | 알림을 켜면 항상 | 이게 없으면 알림을 못 보냅니다 |
| 시각·시간대·호칭 | 알림을 켜면 항상 | 언제 어떻게 부를지 |
| 미완료 할 일 목록 | "할 일 참고" 를 켰을 때만 | 브리핑에서 마감을 짚으려면 |
| 구글 갱신 토큰 | "오늘 일정 참고" 를 켰을 때만 | 브리핑에서 오늘 일정을 보려면 |

**대화 내용은 어떤 경우에도 저장되지 않습니다.**

### 설정 절차

**1. VAPID 키 만들기** (푸시 서명용, 한 번만)

```bash
npm run vapid
```

나온 세 줄을 배포 환경변수에 넣습니다.

**2. 저장소 붙이기**

Vercel 프로젝트 → **Storage** → **Upstash for Redis** 를 연결하면 `KV_REST_API_URL` / `KV_REST_API_TOKEN` 이 자동으로 들어옵니다. Upstash 를 직접 쓰신다면 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` 도 그대로 인식합니다.

무료 등급으로 충분합니다 — 저장되는 것은 기기 하나당 1KB 남짓입니다.

**3. 크론 확인**

`vercel.json` 에 15분마다 도는 크론이 이미 들어 있습니다.

```json
"crons": [{ "path": "/api/push/tick", "schedule": "*/15 * * * *" }]
```

> **Vercel Hobby 요금제는 크론이 하루 한 번만 돕니다.** 그 경우 위 스케줄을 `0 23 * * *` 처럼 하루 한 번으로 바꾸고 (UTC 기준이니 한국 시각 08:00 은 전날 23:00), 앱의 브리핑 시각도 거기에 맞추세요. Pro 요금제면 15분 간격이 그대로 동작합니다.

`CRON_SECRET` 을 환경변수에 넣으면 Vercel 크론이 보낸 요청만 받습니다. 권장합니다.

**4. 아이폰에서 켜기**

- 반드시 **홈 화면에 추가한 아이콘**으로 열어야 합니다. 사파리 탭에서는 iOS 가 알림 권한 요청 자체를 막습니다 (iOS 16.4 이상 필요).
- 설정 → **헤뤼싀가 먼저 말 걸기** → 아침 브리핑 켜기 → 시각 선택
- **시험 알림 보내기** 로 바로 확인해 보세요.

### 브리핑에 무엇이 담기나

헤뤼싀가 대화창에서와 똑같은 인격으로 3~5문장을 씁니다. 오늘 일정 중 가장 중요한 것 하나를 짚고, 마감이 임박한 할 일을 알리고, 오늘 무엇부터 하면 좋을지 한 줄 제안합니다. **위에 없는 사실은 지어내지 않도록** 프롬프트에서 못박았습니다 — 캘린더를 공유하지 않으셨다면 일정 이야기를 아예 꺼내지 않습니다.

같은 날 두 번 가지 않고, 예약 시각을 90분 넘게 지나면 그날은 거릅니다 (한밤중에 아침 인사를 하지 않도록).

## 두 가지 연결 모드

설정 화면에서 고릅니다.

- **서버 프록시** (기본, 권장) — 브라우저는 `/api/chat` 만 호출하고, API 키는 서버 환경변수에만 있습니다. 키가 기기에 남지 않습니다.
- **직접 연결** — 서버 없이 브라우저가 Anthropic API를 직접 호출합니다. GitHub Pages 같은 정적 호스팅에서도 돌아가지만, **API 키가 이 기기의 localStorage에 저장됩니다.** 내 폰에서만 쓰세요.

---

## 대화는 어디에 저장되나

대화·자료실·구글 토큰은 이 기기의 `localStorage` 에, 첨부파일은 `IndexedDB` 에만 저장됩니다. 서버(`/api/chat`)는 요청을 받아 Anthropic으로 전달하고 도구를 돌린 뒤 결과를 돌려줄 뿐, 아무것도 기록하지 않습니다.

**단 하나의 예외는 아침 브리핑입니다.** 헤뤼싀가 기기 없이 먼저 말을 걸려면 서버가 알림 주소를 알아야 하므로, 그것만 저장됩니다 (위 “먼저 말 걸게 하기” 참고). 대화 내용은 그때도 저장되지 않습니다. 기기를 바꾸면 대화는 따라오지 않습니다. 설정 화면에서 대화방별로, 또는 전부 지울 수 있습니다.

### 헤뤼싀 성격을 바꾸려면

`js/persona.js` 의 `corePersona()` 안 문장을 고치면 모든 부서에 한꺼번에 반영됩니다. 호칭(대표님/보스/님)과 "나에 대하여" 메모는 앱 설정 화면에서 바로 바꿀 수 있습니다.

## 만들어진 기능

- iMessage 말풍선 (꼬리, 연속 메시지 묶음, 파란/회색, 라이트·다크)
- 스트리밍 응답 — 글자가 실시간으로 찍힙니다. 중간에 멈출 수 있습니다.
- 타이핑 인디케이터, 전달됨 표시, 날짜 구분선
- 길게 눌러 탭백(❤️👍👎😂‼️❓)
- 대화 목록 · 고정 대화 · 검색 · 안 읽음 표시
- 부서 배지 — 헤뤼싀가 어느 팀에 넘겼는지 말풍선 위에 표시
- 빈 대화방의 추천 질문 칩
- 실패 시 오류 말풍선 + 다시 시도
- 웹 검색·코드 실행·파일 생성 — 도구를 쓰는 동안 "웹을 찾아보는 중…" 이 실시간으로 보임
- 사진·PDF·문서 첨부 — 작성창 + 버튼, 보낸 사진은 말풍선에 그대로
- 구글 캘린더 일정 관리, 지메일 검색·정독·답장 초안
- 메일 발송 확인 카드 — 헤뤼싀는 초안까지만, 발송은 사람이
- 아침 브리핑 — 예약 시각에 헤뤼싀가 먼저 알림을 보내고, 그 내용이 대화에 남음
- 엑셀·문서·발표자료 첨부와 저장
- 부서를 잇는 공용 자료실 (할 일·메모·사람)
- 얼굴 사진 지정 — 헤뤼싀와 각 팀장의 아바타를 내 사진으로 교체
- 홈 화면 추가(PWA), 오프라인에서도 앱은 열림
- 접속 코드, 요청 레이트 리밋
